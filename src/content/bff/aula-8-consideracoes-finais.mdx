<p>O que mais se confunde é o BFF com o gateway, e a diferença é de natureza:</p>

<HowItWorks>
<ol class="flow steps">
  <li>O <strong>gateway</strong> é infraestrutura genérica: roteia, confere o JWT e limita o robô. Serve a todo mundo do mesmo jeito.</li>
  <li>O <strong>BFF</strong> é código de produto: compõe, adapta e decide o fallback de <strong>uma</strong> tela. É do time do frontend.</li>
  <li>O caminho de uma chamada do app fica <code>app → gw-loja → bff-app → serviços</code>.</li>
  <li>O gateway olha para a porta de entrada, o BFF olha para a tela, e os serviços cuidam das regras.</li>
</ol>
</HowItWorks>

<WhyItMatters>
  <li><strong>Um backend por frontend.</strong> Cada tela pede o que precisa e recebe só isso.</li>
  <li><strong>O cuidado:</strong> BFF demais duplica lógica. A regra de negócio fica no serviço.</li>
  <li><strong>O custo:</strong> mais peças para publicar, medir e proteger. O BFF só compensa quando a diferença entre canais é real.</li>
</WhyItMatters>

<p class="gancho">Entre o BFF e os serviços, e entre os próprios serviços, cada chamada precisa de timeout, retry, criptografia e métrica, e cada time está escrevendo isso do seu jeito, em cada linguagem. Falta saber se dá para colocar isso na rede, uma vez só: é o assunto do módulo 10, Service Mesh.</p>
