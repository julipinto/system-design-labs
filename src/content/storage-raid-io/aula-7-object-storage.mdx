<p>A loja guarda 500 mil fotos como o gato.jpg, e uma árvore de pastas com tantas fotos fica pesada. O object storage tira a árvore: cada foto tem uma chave, e o servidor pede a foto por ela.</p>

<OneLiner>object storage guarda cada coisa como um objeto (conteúdo, metadados e uma chave única) num bucket, e você a acessa por uma API, sem pastas de verdade.</OneLiner>

  <p>Na figura, clique em <strong>Próximo passo</strong> e veja o gato.jpg virar um objeto, receber uma chave e ser lido por outro servidor só com a URL.</p>
</DoIt>

<HowItWorks>
<ol class="flow steps">
  <li>A loja cria um <strong>bucket</strong> (um "balde") com nome único: <code>loja-fotos</code>.</li>
  <li>O gato.jpg vira um <strong>objeto</strong>: os 2.457.600 bytes, mais metadados (<code>image/jpeg</code>, <code>produto=4521</code>) e uma chave (<strong>key</strong>): <code>produtos/gatos/gato.jpg</code>.</li>
  <li>Tudo se faz por <strong>API HTTP</strong>: PUT para gravar, GET para ler, DELETE para apagar. Sem montar disco. O B e o navegador do cliente leem pela mesma URL.</li>
  <li>As barras da chave parecem pastas, mas são só parte do nome. O bucket é plano, e listar <code>produtos/gatos/</code> é filtrar chaves pelo prefixo.</li>
  <li>O serviço <strong>replica e distribui</strong> sozinho, entre discos e até entre locais. O preço é que não dá para editar o meio do objeto: corrigir 4 KB do cabeçalho reenvia os 2,4 MB inteiros.</li>
</ol>
</HowItWorks>

<WhyItMatters>
  <li>É o lugar das fotos da loja, dos backups e dos arquivos grandes: capacidade quase ilimitada e barata.</li>
  <li>Escala na horizontal e é cloud native. Em troca, não serve para banco de dados nem para editar um byte no meio do arquivo.</li>
  <li>Cada acesso é uma chamada de rede, com dezenas de milissegundos de latência, mais que um disco. Use CDN na frente para fotos.</li>
</WhyItMatters>

<Deep min={3}>
  <h4 class="deep-h">Falar com o S3 (exemplos)</h4>
  <pre><code>{"aws s3 cp gato.jpg s3://loja-fotos/produtos/gatos/gato.jpg\naws s3 ls s3://loja-fotos/produtos/gatos/\naws s3api head-object --bucket loja-fotos --key produtos/gatos/gato.jpg\n# o head-object mostra ContentLength, ContentType, ETag e metadados"}</code></pre>
  <h4 class="deep-h">Anatomia do objeto</h4>
  <ul>
    <li><strong>Dados:</strong> os bytes da foto.</li>
    <li><strong>Metadados:</strong> tipo de conteúdo, data, etiquetas que você define.</li>
    <li><strong>Chave:</strong> o identificador único dentro do bucket.</li>
  </ul>
  <h4 class="deep-h">Durabilidade</h4>
  <p>O S3 Standard promete 99,999999999% (11 noves) de durabilidade: com 10 milhões de objetos, a expectativa é perder um a cada 10 mil anos. Isso vem de guardar várias cópias em locais diferentes.</p>
  <h4 class="deep-h">Outros exemplos</h4>
  <p>Azure Blob Storage, Google Cloud Storage e, para rodar em casa, MinIO e Ceph.</p>
  <h4 class="deep-h">Ciclo de vida</h4>
  <p>Regras automáticas movem objetos antigos para camadas mais baratas ou os apagam. Útil para os backups da loja.</p>
