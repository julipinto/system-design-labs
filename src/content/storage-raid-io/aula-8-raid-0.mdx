<p>Fotos e backups já têm casa. O pedidos.db ainda mora num disco só, e esse disco tem dois defeitos: é limitado em velocidade e, se queimar, leva o arquivo junto. A saída é juntar vários discos e tratá-los como um só. Isso é um <strong>RAID</strong> (Redundant Array of Independent Disks).</p>

<OneLiner>RAID 0 fatia os dados e espalha entre os discos para somar a velocidade, mas não guarda nenhuma cópia: um disco que falha derruba tudo.</OneLiner>

</DoIt>

<HowItWorks>
<ol class="flow steps">
  <li>A loja junta <strong>4 discos de 1 TB</strong> (D1 a D4) atrás de uma <strong>controladora RAID</strong>. Ela recebe o pedidos.db e o corta em blocos: A1, A2, A3…</li>
  <li>No RAID 0, a controladora espalha os blocos em <strong>faixas (stripes)</strong>: A1 vai para o D1, A2 para o D2, A3 para o D3, A4 para o D4. A faixa seguinte recomeça no D1 (A5).</li>
  <li>Os 4 discos leem e gravam <strong>ao mesmo tempo</strong>: a velocidade chega a ~4x.</li>
  <li>Como nada é copiado, a capacidade é a soma: 4 x 1 TB = <strong>4 TB úteis</strong>.</li>
  <li>Aí vem o custo. Numa noite o D2 queima e leva A2 e A6. Cada arquivo tem pedaços em todos os discos, então o pedidos.db fica com buracos e não abre. <strong>Um disco falha, tudo é perdido.</strong> Trocar o D2 só dá um disco vazio: só o backup restaura.</li>
</ol>
</HowItWorks>

<WhyItMatters>
  <li>Serve para dado que pode ser refeito: cache, área temporária, renderização.</li>
  <li>Mais discos, mais chance de falha: 4 discos têm 4x o risco de perder tudo.</li>
  <li>Nunca para o pedidos.db nem para backups. Para proteger o arquivo, a próxima aula copia cada bloco.</li>
</WhyItMatters>

<Deep min={3}>
  <h4 class="deep-h">Contas</h4>
  <ul>
    <li><strong>Mínimo:</strong> 2 discos.</li>
    <li><strong>Capacidade útil:</strong> N x tamanho. 4 x 1 TB = 4 TB (100%).</li>
    <li><strong>Falhas toleradas:</strong> 0.</li>
    <li><strong>Penalidade de escrita:</strong> 1 (cada escrita é uma operação).</li>
    <li><strong>Leitura e escrita:</strong> até N vezes um disco só.</li>
  </ul>
  <h4 class="deep-h">Risco em números (exemplo)</h4>
  <p>Se cada disco tem 3% de chance de falhar no ano, o RAID 0 de 4 discos perde tudo com 1 - 0,97^4 = 11,5%. Um disco só: 3%.</p>
  <h4 class="deep-h">Tamanho da fatia</h4>
  <p>O <strong>stripe size</strong> (por exemplo 64 KB) é quanto vai a cada disco antes de passar ao próximo. Fatia pequena favorece arquivos pequenos em paralelo, fatia grande favorece leitura sequencial.</p>
