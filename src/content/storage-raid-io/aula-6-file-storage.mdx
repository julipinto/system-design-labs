<p>O volume da aula passada guarda 600 blocos do gato.jpg e nada mais: nenhum nome, nenhuma pasta. Alguém precisa guardar o mapa que liga o nome aos blocos. Esse alguém é o sistema de arquivos, e o que ele entrega é o file storage.</p>

<OneLiner>file storage organiza os dados em pastas e arquivos com nome, e o sistema de arquivos faz a ponte entre esses nomes e os blocos do disco.</OneLiner>

<HowItWorks>
<ol class="flow steps">
  <li>Os dados ficam numa <strong>árvore de pastas</strong>: <code>/produtos/gatos/gato.jpg</code>. A loja usa um file storage gerenciado (o <strong>EFS</strong>, da AWS), e os três servidores montam a mesma árvore em <code>/mnt/efs</code>.</li>
  <li>O <strong>caminho + nome</strong> identifica o arquivo. Dois arquivos não têm o mesmo nome na mesma pasta.</li>
  <li>Para abrir o arquivo, o sistema anda pasta por pasta: raiz, <code>produtos</code>, <code>gatos</code>, <code>gato.jpg</code>. Em cada pasta confere se o servidor pode entrar (o <code>x</code> de rwx).</li>
  <li>Ao chegar, vem a ficha do arquivo, os <strong>metadados</strong>: dono <code>loja</code>, grupo <code>web</code>, permissão <code>rw-r--r--</code>, 2.457.600 bytes, data. No Linux, essa ficha é o <strong>inode</strong> (o do gato.jpg é o 1311), que aponta para os blocos 2048 a 2647.</li>
  <li>Dois servidores querem editar a mesma foto? O sistema dá um <strong>lock</strong> ao primeiro, e o segundo espera. Sem isso, as gravações se misturariam.</li>
</ol>
</HowItWorks>

<WhyItMatters>
  <li>É o que as pessoas e os programas já conhecem: abrir, salvar, mover, dar permissão. Renomear a pasta <code>gatos</code> para <code>felinos</code> é uma operação só, com 1 foto ou 1 milhão dentro.</li>
  <li>Funciona bem para dados compartilhados e organizados em pastas, como as fotos de produto que o time edita.</li>
  <li>A hierarquia complica a escala: listar uma pasta com milhões de arquivos fica lento.</li>
</WhyItMatters>

  <h4 class="deep-h">Sistemas de arquivos comuns</h4>
  <ul>
    <li><strong>ext4:</strong> padrão do Linux, simples e estável.</li>
    <li><strong>XFS:</strong> bom para arquivos grandes e muita concorrência.</li>
    <li><strong>NTFS:</strong> o do Windows.</li>
  </ul>
  <h4 class="deep-h">Bloco x arquivo</h4>
  <p>O block storage guarda blocos e não sabe o que é um arquivo. O sistema de arquivos é a camada que dá nome e pasta a esses blocos. Em file storage, quem entrega isso pela rede é o servidor (NAS ou EFS).</p>
  <h4 class="deep-h">RAID por baixo</h4>
  <p>É comum o servidor de arquivos guardar os dados sobre um RAID (aulas 8 a 13), para ganhar velocidade e tolerância a falhas.</p>
