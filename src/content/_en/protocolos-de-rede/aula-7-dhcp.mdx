<HowItWorks>
<p>The phone has no IP and doesn't know who the server is, so everything starts with shouting. The acronym <strong>DORA</strong> covers the 4 steps: Discover, Offer, Request, Acknowledgment.</p>
<ol class="flow steps">
  <li><strong>Discover:</strong> the client doesn't have an IP yet, so it shouts by <strong>broadcast</strong> over UDP (ports 68 and 67): "is there a DHCP server out there?"</li>
  <li><strong>Offer:</strong> only the server answers, with an offer of IP, mask, gateway, DNS and lease time.</li>
  <li><strong>Request:</strong> the client picks an offer and asks for it, also by broadcast, because it can't use the IP yet.</li>
  <li><strong>Acknowledgment:</strong> the server confirms. The IP is the client's for the length of the <strong>lease</strong>.</li>
</ol>
</HowItWorks>

<p>With IP, gateway and DNS in hand, Lena's phone can finally use the DNS from lesson 6 and open the connections from lessons 4 and 5.</p>

<WhyItMatters>
  <li>Thanks to this, instances, containers and devices join the network with no manual configuration, with IPs being reused.</li>
  <li>The flip side: an exhausted address pool or a DHCP server that is down leaves new devices with no network.</li>
  <li>The classic symptom is a <code>169.254.x.x</code> IP.</li>
</WhyItMatters>

<Deep min={1}>
  <p>Without DHCP, each device would need manual configuration, with the risk of IP conflicts.</p>
  <p>The DHCP server (at home, the Wi-Fi router) keeps a pool of addresses and <strong>leases</strong> them for a while. When the device leaves, the address goes back to the pool.</p>
  <p>The IP is renewed before it expires. In the public cloud this is usually abstracted away.</p>
