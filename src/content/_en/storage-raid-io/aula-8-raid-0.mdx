<p>Photos and backups have a home now. pedidos.db still lives on a single disk, and that disk has two flaws: its speed is limited and, if it dies, it takes the file with it. The way out is to combine several disks and treat them as one. That is a <strong>RAID</strong> (Redundant Array of Independent Disks).</p>

<OneLiner>RAID 0 slices the data and spreads it across the disks to add up the speed, but keeps no copy: one failed disk brings everything down.</OneLiner>

<HowItWorks>
<ol class="flow steps">
  <li>The store combines <strong>4 disks of 1 TB</strong> (D1 to D4) behind a <strong>RAID controller</strong>. It receives pedidos.db and cuts it into blocks: A1, A2, A3…</li>
  <li>In RAID 0, the controller spreads the blocks in <strong>stripes</strong>: A1 goes to D1, A2 to D2, A3 to D3, A4 to D4. The next stripe starts again at D1 (A5).</li>
  <li>All 4 disks read and write <strong>at the same time</strong>: speed reaches ~4x.</li>
  <li>Since nothing is copied, the capacity is the sum: 4 x 1 TB = <strong>4 TB usable</strong>.</li>
  <li>Then comes the cost. One night D2 dies and takes A2 and A6 with it. Every file has pieces on all the disks, so pedidos.db is left with holes and won't open. <strong>One disk fails, everything is lost.</strong> Swapping D2 only gives an empty disk: only the backup restores it.</li>
</ol>
</HowItWorks>

<WhyItMatters>
  <li>It suits data that can be rebuilt: cache, scratch space, rendering.</li>
  <li>More disks, more chances of failure: 4 disks carry 4x the risk of losing everything.</li>
  <li>Never for pedidos.db or for backups. To protect the file, the next lesson copies each block.</li>
</WhyItMatters>

<Deep min={3}>
  <h4 class="deep-h">The math</h4>
  <ul>
    <li><strong>Minimum:</strong> 2 disks.</li>
    <li><strong>Usable capacity:</strong> N x size. 4 x 1 TB = 4 TB (100%).</li>
    <li><strong>Failures tolerated:</strong> 0.</li>
    <li><strong>Write penalty:</strong> 1 (each write is one operation).</li>
    <li><strong>Read and write:</strong> up to N times a single disk.</li>
  </ul>
  <h4 class="deep-h">Risk in numbers (example)</h4>
  <p>If each disk has a 3% chance of failing in a year, a 4-disk RAID 0 loses everything with 1 - 0.97^4 = 11.5%. A single disk: 3%.</p>
  <h4 class="deep-h">Stripe size</h4>
  <p>The <strong>stripe size</strong> (for example 64 KB) is how much goes to each disk before moving on to the next. A small stripe favors small files in parallel, a large stripe favors sequential reads.</p>
