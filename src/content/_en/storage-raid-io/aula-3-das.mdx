<p>With IOPS and latency in hand, the store needs to write <strong>gato.jpg</strong>, a product photo (2.4 MB). The shortest path to a disk is no path at all: the disk sits inside the server.</p>

<OneLiner>DAS is a disk attached directly to the server: the shortest and fastest path, but only that server sees the disk.</OneLiner>

</DoIt>

<HowItWorks>
<ol class="flow steps">
  <li>The store's server A has a <strong>1 TB NVMe SSD</strong> installed inside it.</li>
  <li>The operating system talks to the disk over the bus (<strong>PCIe</strong>, SATA or USB). There is no network in the path.</li>
  <li>gato.jpg is written to <code>/data/produtos/gato.jpg</code>. With no hops, a 4 KB read takes about <strong>0.1 ms</strong>.</li>
  <li>The price shows up when the store grows: server B looks for the same file and can't find it. Only A sees that disk.</li>
  <li>To grow, you have to <strong>add more disks to the machine</strong> and migrate data by hand. The patch is copying the photo to B, and now there are two photos.</li>
</ol>
</HowItWorks>

<WhyItMatters>
  <li>A database that needs minimal latency usually runs on DAS (or on an equivalent volume).</li>
  <li>It only scales up: few disks fit in a server, and the machine becomes a single point of failure.</li>
  <li>If the server goes down, the disk becomes inaccessible with it. RAID and replicas cover that (lessons 8 to 13).</li>
</WhyItMatters>

<Deep min={3}>
  <h4 class="deep-h">When to use</h4>
  <ul>
    <li>Very low latency: transactional database, cache, temporary files.</li>
    <li>Simple environment, no need to share.</li>
  </ul>
  <h4 class="deep-h">Limits</h4>
  <ul>
    <li>Little horizontal scalability.</li>
    <li>Expanding means opening the machine or swapping the disk.</li>
    <li>No sharing: copying to another server is manual work.</li>
  </ul>
  <h4 class="deep-h">See it on Linux</h4>
