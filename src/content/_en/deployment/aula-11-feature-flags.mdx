<p class="ponte">In the last lesson shadow showed that the risk is not always infrastructure: sometimes it is the <strong>rule</strong> the customer sees, like the shipping calculation. For that case you need to separate two things that rolling, blue/green and canary join together: <strong>deploying</strong> the code and <strong>releasing</strong> the behavior. That is what a <em>feature flag</em> does.</p>

<OneLiner>A <strong>feature flag</strong> separates <strong>deploying</strong> from <strong>releasing</strong>: the 2.5.0 code goes to 100% of the pods with the <code>frete_v2</code> flag <strong>off</strong>, and releasing is turning it on, by customer, in percentages. It gives the business a button, and going back takes <strong>seconds</strong> with no new deploy.</OneLiner>

<HowItWorks>
<ol class="flow steps">
  <li><strong>Deploy without releasing.</strong> 2.5.0 goes live through the safe rolling (lesson 3), with the <code>frete_v2</code> flag off: no effect on the customer, and the new code is already on every pod.</li>
  <li><strong>The decision is a stable calculation on the customer.</strong> <code>bucket = murmur3("frete_v2:" + cliente_id) mod 100</code>, and <code>on = bucket &lt; percentage</code>. The same customer always lands on the same side; the function is the one from module 16.</li>
  <li><strong>The store's buckets.</strong> <code>caio-58</code> → <strong>3</strong>, <code>lena-77</code> → <strong>19</strong>, <code>bia-31</code> → <strong>38</strong>, <code>mkt-01</code> → <strong>41</strong>, <code>davi-12</code> → <strong>94</strong>.</li>
  <li><strong>The ladder.</strong> At <strong>1%</strong> nobody in the sample is on. At <strong>10%</strong> only Caio (Rio: the Recife defect does <strong>not show</strong>). At <strong>20%</strong> Lena comes in (Recife: it shows). At <strong>50%</strong>, Caio, Lena, Bia and <code>mkt-01</code>; at <strong>100%</strong>, Davi.</li>
  <li><strong>The function spreads evenly.</strong> Across 100,000 customers (<code>c-0</code> to <code>c-99999</code>), <strong>985</strong> fall below 1, <strong>9,878</strong> below 10 and <strong>49,909</strong> below 50.</li>
</ol>
</HowItWorks>

<p>The same calculation, with another salt, gives the <code>nova_home</code> flag from module 9: <code>lena-77</code> → 80, <code>bia-31</code> → 2, <code>caio-58</code> → 72, <code>davi-12</code> → 67, <code>mkt-01</code> → 87. The <strong>flag name goes into the hash</strong>: each flag draws the customers again, and whoever is "first" on one flag is not first on the other.</p>

<h3 class="sec">Types and lifespan</h3>

<p>Fowler separates four types, with different lifespans: <em>release toggle</em> (days, and it should be <strong>removed</strong> afterwards), <em>experiment toggle</em> (A/B), <em>ops toggle</em> (turning off an expensive piece: the <em>kill switch</em>) and <em>permission toggle</em> (who is allowed: the article's customer cluster). The debt is real: each flag <strong>doubles</strong> the possible states, and 5 flags are <strong>32</strong> combinations.</p>

<h3 class="sec">Where it is decided and how long it takes</h3>

<p>The decision lives in <code>bff-app</code> (module 9: the screen flag) or in <code>pedidos</code> (the rule). The pod keeps the value in a local cache with a <strong>30 s TTL</strong> (the same pattern as module 5): turning it on or off takes <strong>up to 30 s</strong> to reach every pod. In that interval two pods can disagree, and that is why the calculation is <strong>per customer</strong> and not per request: the same person does not see both versions. The standard API for this is <strong>OpenFeature</strong>.</p>

<h3 class="sec">What if it goes wrong: the flag service goes down and the default is wrong</h3>

<p>The flag service goes down. The pod uses the <strong>last cached value</strong> and, when the cache expires, the <strong>compiled default</strong>. If the default was <code>true</code> (someone forgot to set it back after the launch), the feature turns on for <strong>everyone</strong> at once, <strong>without a deploy and without a canary</strong>: the zero shipping reaches all of Recife. The rule is <strong>default = old behavior (<code>false</code>)</strong>, and the flag is <strong>removed</strong> from the code as soon as it reaches 100% and stabilizes.</p>

<WhyItMatters>
  <li><strong>Deploying and releasing are different decisions.</strong> The flag gives the business the button, without asking for a deploy.</li>
  <li><strong>The calculation is per customer.</strong> The same bucket always gives the same side, even with pods disagreeing for 30 s.</li>
  <li><strong>Going back is turning it off.</strong> Up to 30 s, against the 90 s of rolling.</li>
  <li><strong>An old flag is debt.</strong> 5 flags are 32 combinations; remove the flag as soon as the launch stabilizes.</li>
</WhyItMatters>
