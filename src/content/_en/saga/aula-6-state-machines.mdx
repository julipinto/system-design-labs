<p class="ponte">In the last lesson the orchestrator needed a place to note <strong>which step each saga is at</strong>, and that place is a database. What's left is giving shape to what gets noted. The shape is a <strong>state machine</strong>: the saga is in a state, an event arrives, and the pair (state, event) says where to go and what to do.</p>

<OneLiner>The saga is a <strong>state machine</strong>: given the <strong>current state</strong> and the <strong>event</strong> that arrived, it knows <strong>where it goes</strong> and <strong>what it does</strong>. The <strong>conditional transition</strong> (<code>UPDATE … WHERE estado = de</code>) makes it <strong>safe against repeats and reordering</strong>: the same <code>PedidoPago</code> delivered twice is ignored without special code.</OneLiner>

<HowItWorks>
<ol class="flow steps">
  <li><strong>Four questions.</strong> The article sums the machine up in four: <em>What event is this? Where am I? Where do I go? What do I do here?</em> <code>EstoqueIndisponivel</code> arrived (event), the saga is in <code>RESERVANDO</code> (where), goes to <code>COMPENSANDO</code> (where to) and orders the refund (what it does).</li>
  <li><strong>The store's states.</strong> On success: <code>NOVO</code> → <code>COBRANDO</code> → <code>PAGO</code> → <code>RESERVANDO</code> → <code>RESERVADO</code> → <code>AGENDANDO</code> → <code>FINALIZADO</code>. On 1057's failure: … → <code>COMPENSANDO</code> → <code>ESTORNANDO</code> → <code>CANCELADO</code>.</li>
  <li><strong>Final states.</strong> There are three: <code>FINALIZADO</code>, <code>CANCELADO</code> and <code>INTERVENCAO</code>. The last is the only one that <strong>calls a person</strong>: the compensation didn't go through, and a human decides (lesson 7).</li>
  <li><strong>The transition is conditional.</strong> The <code>transitar</code> function does <code>UPDATE saga SET estado = para, versao = versao + 1 WHERE saga_id = … AND estado = de</code> and only writes to the log if the <code>UPDATE</code> affected <strong>1 row</strong>. The saga only advances from the state it is really in.</li>
  <li><strong>The duplicate comes for free.</strong> The same <code>PedidoPago</code> (<code>e-1902</code>) arrived again at <strong>20:15:41.210</strong>. <code>transitar('s-1057','COBRANDO','PAGO',…)</code> returned <strong><code>f</code></strong>: the saga was no longer in <code>COBRANDO</code>, so nothing changed and <strong>nothing</strong> went to the log.</li>
</ol>
</HowItWorks>

<pre><code>{String.raw`-- core of transitar(saga, de, para, evento, dados, em), PostgreSQL 14.24 (simplified form)
UPDATE saga
   SET estado = para, versao = versao + 1, atualizada_em = em
 WHERE saga_id = saga AND estado = de;
-- if ROW_COUNT = 1: INSERT INTO saga_log (saga_id, de, para, evento_id, dados, em) ...; returns 't'
-- if ROW_COUNT = 0: writes nothing; returns 'f'

transitar('s-1057','COBRANDO','PAGO','e-1902', …)  ->  f   (20:15:41.210, the duplicate)`}</code></pre>

<h3 class="sec">What if it goes wrong: the saga that stalled</h3>

<p>The PSP never reports the Pix (the webhook got lost, or Davi gave up). The saga stays in <code>COBRANDO</code> <strong>forever</strong>: no event arrives, so no transition happens. The way out is a <strong>deadline per state</strong> (the Pix charge expires in 30 min, in the example) and a <strong>watchdog</strong> that looks for stalled sagas and expires them, which triggers the compensation:</p>

<pre><code>{String.raw`SELECT saga_id, estado
  FROM saga
 WHERE estado NOT IN ('FINALIZADO','CANCELADO')
   AND atualizada_em < now() - interval '30 minutes';`}</code></pre>

<p>Run on PostgreSQL 14.24 on Oct 20, 2026, the watchdog found a test saga, <code>s-teste</code>, stalled in <code>COBRANDO</code> since 19:20.</p>

<WhyItMatters>
  <li><strong>The state says it all.</strong> Where 1057 is, what's left and what gets undone all come from the saga's row.</li>
  <li><strong>Repeating is safe.</strong> The conditional transition ignores the duplicate and the out-of-order message without special code.</li>
  <li><strong>A final state has a name.</strong> <code>FINALIZADO</code>, <code>CANCELADO</code> and <code>INTERVENCAO</code>: the last is the one that calls a person.</li>
  <li><strong>A stalled saga is a state.</strong> With no deadline and no watchdog, <code>COBRANDO</code> lasts forever.</li>
</WhyItMatters>
